# Limit Order Matching Engine

A single-threaded limit order book matching engine implementing price-time priority, written in modern C++.

> **Status:** Stage 1 complete — core matching engine and API. Stage 2 (concurrent producer/consumer architecture via MPSC queue) is planned but not yet started.

## Overview

This project implements the core data structures and matching logic behind an exchange limit order book: resting orders sit in price-ordered books, incoming orders match against the best available price on the opposite side, and partial fills, cancellations, and best bid/ask queries are all supported.

## Design

- **Price-time priority matching** — orders at the same price level fill in FIFO order.
- **`std::map<Price, std::list<Order>>` per side** — bids are ordered high-to-low (`std::greater<>`), asks low-to-high, so the best price is always `begin()`.
- **O(1) order lookup and cancellation** — an `unordered_map<OrderID, OrderLocator>` stores each resting order's side, price, and list iterator, avoiding a scan of the book on cancel.
- **`int64_t` tick-based pricing** — avoids floating-point representation issues in price comparisons.
- **Monotonic sequence counter** — every order is stamped with a strictly increasing `Sequence` on entry, preserving arrival order for time priority and for trade reporting.

## API

```cpp
class OrderBook {
public:
    std::vector<Trade> submit(Order order);   // submit a new order; returns any resulting trades
    bool cancel(OrderID orderID);              // cancel a resting order by ID

    bool bestBid(Price &out) const;            // highest resting bid price, if any
    bool bestAsk(Price &out) const;             // lowest resting ask price, if any
    Quantity depthAt(OrderAction side, Price price) const; // total resting quantity at a price level
};
```

- `submit` handles both market and limit orders, matches against the opposite book, and rests any unfilled limit quantity. It returns every `Trade` generated by the submission.
- `cancel` removes a resting order in O(1) via the ID index.
- `bestBid` / `bestAsk` return `false` if that side of the book is empty.
- `depthAt` sums resting quantity across all orders at a given price level.

## Core types

| Type | Description |
|---|---|
| `Order` | Tracks action (buy/sell), type (market/limit), price, initial/remaining quantity, status, and sequence number. Exposes `fill()` and `cancel()` with internal state-transition assertions. |
| `Trade` | Immutable record of a match: maker order ID, taker order ID, price, quantity, sequence. |
| `OrderStatus` | `RESTING`, `PARTIALLY_FILLED`, `FILLED`, `CANCELLED` |

## Testing

Stage 1 is covered by a hand-written test suite (seven cases) exercising matching, partial fills, cancellation, and best bid/ask/depth queries. All tests pass.
